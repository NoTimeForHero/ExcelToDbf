# Ручная проверка GUI после выделения общего ядра

Статус: выполняет пользователь. Автоматическая проверка GUI остановлена по его просьбе. Исправление путей собрано, но повторный успешный запуск GUI не подтверждён.

## Подготовка

Использовать новую сборку `App\bin\Release\ExcelToDbf.exe` либо свежую копию всей Release-поставки. Нужны EXE, его config, каталог DLL и остальные файлы поставки; один EXE отдельно не переносить.

Для проверки примеров взять отдельную копию поставки, сохранить её прежний `config.js` и использовать `config.example.js` как тестовый `config.js`. Рабочий конфиг фирмы не заменять. Старое окно ошибки из `artifacts\package-smoke-...` относится к предыдущей тестовой копии, а не к исправленной сборке.

В этой копии проверить, что предзагрузка конфигурации отключена и URL автообновления не задан, чтобы локальный тест не подменил правила с сервера. У свежей поставки без `Preload.json` предзагрузка по умолчанию выключена.

## 1. Запуск и расположение служебных файлов

- Открыть GUI обычным способом. Должны появиться главное окно, заголовок фирмы из конфига и выбор файлов, без критического диалога Unity.
- Запустить ту же копию из другой рабочей директории, например PowerShell из временного каталога:

```powershell
Start-Process -FilePath 'ПОЛНЫЙ_ПУТЬ_К_КОПИИ\ExcelToDbf.exe' -WorkingDirectory $env:TEMP
```

- Не должно быть отказа доступа к `Preload.json` в папке Codex, WindowsApps или другой рабочей директории. `config.js`, `Preload.json` и `LastLaunch.json` должны использоваться рядом с EXE. Последний файл появляется после конвертации.
- Дополнительно проверить копию в пути с пробелами и кириллицей. Для первого запуска директория поставки должна быть доступна для записи.

Ранее подтверждённая ошибка: GUI использовал относительный `Preload.json` и пытался сохранить его в рабочей директории процесса Codex. Пути Preload и LastLaunch теперь, как и config.js, привязаны к директории приложения. Это исправление не требует правок настроек Windows.

## 2. Выбор файлов и уведомления интерфейса

- Выбрать `TestData` в тестовой копии. Должны отобразиться все шесть Excel-примеров, без DBF в списке входных файлов.
- Проверить выбор одного файла, «выбрать всё» и снятие выбора. Счётчик выбранных файлов должен меняться.
- Запустить конвертацию без выбора: ожидается понятное предупреждение, затем можно продолжить работу.
- Во время обычной конвертации должны обновляться имя файла и прогресс; окно не должно зависать.

## 3. Успешные и ошибочные примеры

С примерным конфигом ожидаются следующие результаты:

| Вход | Результат |
| --- | --- |
| Example1.xlsx | Форма 2.21А, 498 записей, SUMMA 54856.94 |
| Example2.xlsx | Форма 2.21Б (с регулярками), 500 записей, SUMMA 55084.96, отрабатывает afterWrite |
| Example3-error.xlsx | Ошибка числа ERROR, исходная строка 9, поле SUMMA |
| Example4.xlsx | Форма 2.21В (плавающий заголовок), 500 записей, SUMMA 55084.96, заполнен адрес в PERSON |
| Example5.xls | Нет подходящей формы в текущем JS-конфиге |
| Example6-js-error.xls | Нет подходящей формы в текущем JS-конфиге; название файла не означает, что нынешний конфиг выберет его |

- Проверить, что ошибка одного файла не мешает обработке следующих.
- В результате должны быть видны выбранная форма, число записей и сообщения ошибок/несовпадений. Номер проблемной строки должен относиться к Excel.
- Политика GUI по перезаписи и частичным DBF сохранена прежней: гарантии атомарной публикации в этой задаче относятся к CLI. Наличие DBF после ошибочного GUI-запуска не подтверждает успех.
- Для проверки содержимого успешных DBF использовать CRM или привычный просмотрщик; числовые ожидания также проверены CLI по фактически записанным данным.

## 4. Повторная обработка и завершение

- Вернуться к выбору файлов и выполнить ещё одну конвертацию в том же процессе GUI: Excel должен создаться заново, без ошибки использования уже закрытого COM-объекта.
- Обработать Example4 отдельно и в наборе после других файлов: динамический заголовок и адрес не должны зависеть от порядка документов.
- Закрыть и снова открыть программу. История последнего запуска должна восстановиться из файла рядом с EXE, если он создан.
- После завершения операции дождаться закрытия экземпляра Excel, созданного конвертером. Заранее открытый пользователем Excel должен оставаться доступным вместе с его книгами.
- Выполнить штатное закрытие GUI; не должно появляться новых исключений.

## 5. Конфиг реальной фирмы

В отдельной копии проверить один привычный успешный документ с локальным JS-конфигом фирмы: распознавание, схема и содержимое DBF, привычный импорт CRM. Затем проверить добавленную новую форму и старые формы на их документах.

Сборка теперь сохраняет существующий `config.js`, а исходный пример обновляет как `config.example.js`. Убедиться, что используется именно нужный конфиг. Старые XML-конфиги этим изменением не мигрируются.

Если обнаружится ошибка, зафиксировать версию сборки, путь и способ запуска, используемый конфиг, входной пример, ожидаемый и фактический результат, текст ошибки и соответствующий лог из `logs`. Рабочие персональные данные перед передачей обезличить.
