# Реализация CLI: наблюдения и проверки

## Базовое состояние, 16 ноября 2026

- Исходная сборка Debug проходит в Visual Studio 2022 MSBuild на .NET Framework 4.7.2.
- Excel 16.0 создаётся через COM; исходные примеры открываются без изменения файлов.
- Исходный запуск MSTest: 19 успешных проверок, 12 ошибок из 31. Десять ошибок вызваны передачей `null` вместо делегата `findRange` в тестовых подстановках; две — устаревшими ожиданиями для `translit` и текста `error`.
- Тестовые подстановки исправлены, ожидаемое поведение базовых функций приведено к действующему коду. Исправлены пропущенные запятые в JS-примерах тестов.
- Локальные конфиги из `App/bin/Debug` сохранены в игнорируемую `artifacts/baseline` перед сборкой. Правки готовой поставки не являются исходниками правил.

Диапазоны исходных примеров, прочитанные установленным Excel:

| Файл | UsedRange |
| --- | --- |
| Example1.xlsx | B2:L509 |
| Example2.xlsx | B2:L520 |
| Example3-error.xlsx | B2:L196 |
| Example4.xlsx | B2:L533 |

Следовательно, количество строк UsedRange нельзя использовать как абсолютный номер последней строки. Проверки чтения блоков должны учитывать смещение диапазона.

## Проблемы, проверяемые в рамках CLI

- Общий JS `context` нескольких форм и сохранение состояния выбранной формы.
- Последний столбец в `GetRow`, границы блоков и номер строки в сообщении об ошибке.
- Успех распознавания без единого `assert`.
- Отличия комментариев в `config.js` от реальных сигнатур API.
- Закрытие COM и отсутствие диалогов, включая вспомогательный CSV-конвертер.
- Наличие частичного DBF после ошибки заключительного хука.

## Отложенные вопросы

- Миграция XML-конфигов фирм выполняется после CLI.
- Исходный post-build сообщает о существующих каталогах и некоторых отсутствующих файлах. Упаковка будет изменена только в объёме, необходимом для надёжной поставки CLI и сохранения локального конфига.
- DBF из `bin/Debug/TestData` ещё не утверждены как эталоны CRM; наличие файла не означает успех обработки.

## Общая библиотека

- Сервисы Excel, JS и DBF, общие модели и функции перенесены в `Engine`. GUI использует `ConversionPipeline`, который будет вызывать и CLI.
- Оставлена текущая платформа .NET Framework 4.7.2. Уведомления общих моделей ReactiveUI сохранены без зависимости библиотеки от Fody и окон.
- Исправлены чтение последнего столбца, границы блоков, абсолютная последняя строка UsedRange и номер исходной строки. `line[0]` остаётся пустым, `line[1]` соответствует A; теперь доступен и `line[endX]`.
- Каждая форма получает собственный `context`. После поиска восстановлен контекст первой подходящей формы. Правило без выполненных `assert` не считается совпадением.
- Excel открывается только для чтения, с отключёнными макросами и обновлением связей; временные COM-ссылки освобождаются. GUI запускает общий цикл на STA-потоке.
- Путь рабочего GUI-конфига привязан к директории приложения, включая предзагрузку. CLI сможет явно выбрать другой путь.
- Сборка Debug и все 36 MSTest проходят, включая интеграционную проверку установленного Excel: 502 строки с 8 по 509, блоки 200/200/102, единичная ячейка и создание DBF через общий цикл.

## Основа CLI

- Добавлен отдельный консольный проект .NET Framework 4.7.2. `doctor`, `check-config`, справка, JSON и коды завершения проверяются через реальный EXE.
- Каждая операция выполняется в отдельном STA-процессе с внешним тайм-аутом. Зарегистрированные процессы Excel идентифицируются по PID, времени создания и имени; чужой ранее открытый Excel не используется.
- Конфиг передаётся явно; путь по умолчанию привязан к EXE. `RuleRuntime` проверяет схему правил без Excel.
- В готовую CLI-сборку явно добавлены зависимости System.Memory, Buffers и Vectors: старый MSBuild не переносит их надёжно через косвенную ссылку на Jint.
- Скрипт `tests/cli-smoke.ps1 -FoundationOnly` проверяет справку, валидный и ошибочный конфиг, аргументы, SHA256, реальный Excel и прерывание бесконечного JS.

## Просмотр документов и распознавание

- `inspect` читает ограниченный A1-диапазон (до 10000 ячеек) первого листа, возвращает список листов, UsedRange, координаты, типы, исходные значения и строковые значения правил.
- `match` возвращает выбранную форму, выполненные assertions, остановленные проверки и неисполненные формы. Отсутствие формы имеет код 1, ошибка JS — отдельный код с этапом и формой.
- `--all-forms` сохраняет результат рабочего поиска, а полный диагностический поиск выполняет в отдельном JS runtime. `fastSearch` рабочего конфига не изменяется.
- Расширена smoke-проверка: диапазон B2:F8, защита от неограниченного вывода, fastSearch и отдельный полный поиск, плавающий заголовок и отсутствие формы.

## Полная конвертация и проверка DBF

- Реализованы `validate` и `convert` через общий с GUI `ConversionPipeline`. Валидация пишет во временную директорию и независимо читает весь DBF обратно, проверяя схему, записи, числа, даты и декодирование.
- Публикация CLI выполняется через временный файл в целевой директории после успешного `afterWrite`. Существующий DBF заменяется только с `--overwrite`; при ошибке старый файл сохраняется.
- Добавлены предупреждения об обрезании строк, потерях кодировки, точности чисел и нераспознанных датах; `--strict` запрещает эти потери. Числовое переполнение — ошибка. В отчёт попадает до 200 предупреждений, общее число сохраняется отдельно.
- Ошибки содержат этап, исходную строку и поле; для ошибок Jint сохраняются стек и доступные координаты JS. Имена полей в словарях JSON сохраняют исходный регистр DBF.
- `--keep-artifacts` сохраняет явно обозначенный проверенный или частичный сбойный DBF. Тайм-аут и Ctrl+C останавливают рабочий процесс, зарегистрированные процессы и незавершённую публикацию.
- Вспомогательный CSV-конвертер сохранён на .NET 3.5 ради прежнего поведения разделителя. Он возвращает код ошибки вместо окна и регистрирует свои процессы для очистки.
- Все шесть исходных примеров проверены CLI: Example1 — 498 записей и SUMMA 54856.94; Example2 и Example4 — по 500 записей и SUMMA 55084.96; Example3-error — INVALID_NUMBER, строка 9, SUMMA=ERROR; Example5 и Example6-js-error — NO_FORM с текущим JS-конфигом. Имя последнего файла не подтверждает наличие ошибки JS в поддерживаемой форме.

## Регрессионный набор готовой поставки

- Добавлены `test --manifest` и `App/TestData/cases.json`: шесть сценариев проверяют распознавание, количество записей, контрольные суммы, значения полей, хуки, плавающий заголовок и ожидаемые ошибки.
- Ожидания хранятся в исходниках вне `bin`; входные пути считаются относительно manifest. Все сценарии запускаются с выбранным `--config` фирмы.
- Сравнение выполняется по типизированным данным, прочитанным из DBF. Служебная дата заголовка не участвует. Допуск чисел задаётся явно и по умолчанию равен нулю.
- Неверное количество записей и контрольная сумма дают отдельные differences и общий REGRESSION_FAILED; пустой или ошибочный manifest отклоняется.
- Это регрессионные ожидания примеров проекта. Они не выдаются за подтверждение коммерческой CRM; существующие DBF из `bin` не включены как утверждённые эталоны.

## Поставка и документация

- В обе сборки копируются инструкции `AGENTS.md`, справочники CLI/JS/DBF, шаблон формы и регрессионные примеры. Сборка App включает консольный EXE рядом с GUI и зависимости в DLL.
- Старый post-build на cmd заменён MSBuild-задачами копирования и переноса. Существующий config.js не заменяется; исходный пример обновляется как config.example.js.
- Добавлены предупреждения UNSUPPORTED_PROPERTY для неизвестных свойств конфигурации: опечатка в параметре не остаётся незаметной.
- Изолированная Release-поставка прошла 95 проверок CLI из другой рабочей директории, с кириллицей и пробелами в пути; проверены относительные ссылки документации. После последующих небольших исправлений проверки повторяются.
- При попытке запуска GUI из процесса Codex обнаружена прежняя зависимость Preload.json от рабочей директории: отказ доступа в WindowsApps. Preload.json и LastLaunch.json привязаны к директории EXE; исправленная Release-сборка создана.
- По просьбе пользователя дальнейшие GUI-проверки переданы ему. Успешный повторный запуск GUI не утверждается. Подготовлен `docs/gui-manual-checks.md` с последовательностью и ожидаемыми результатами.
- Существующий конфиг фирмы `config.русичи.js` из сохранённой локальной поставки проходит check-config (одна форма).

Оставленные предупреждения сборки: прежнее неиспользуемое поле ConfigProvider.container и CS1762 о косвенной ссылке Excel interop через CSV_Converter. Они не мешают сборке и проверкам CLI; смена схемы interop и чистка постороннего кода не входят в задачу.

## Итоговая автоматическая проверка

- Сборки Debug и Release проходят. Последний запуск MSTest: 36 из 36 успешны, включая установленный Excel.
- Изолированная Release-поставка: 111 проверок CLI успешны. Запуск выполнен из другой рабочей директории, с пробелами и кириллицей в путях; исходники в поставку не включались.
- Изолированная Debug-поставка под Windows PowerShell 5.1: 108 проверок успешны. После последнего уточнения обработки ошибок временной директории актуальная Debug-поставка дополнительно прошла все 28 базовых проверок в PowerShell 5.1.
- Проверены сохранение успешного и частичного артефакта, разрешённая замена выхода, отказ от неразрешённой перезаписи и сохранение старого файла после ошибки afterWrite.
- Отдельный тест подтвердил, что более старый конфиг фирмы сохраняется при более новом исходном примере. Хеши существующих Debug/Release config.js после сборки не меняются.
- Ошибка доступа к TEMP возвращается как корректный JSON с кодом процесса 3. Ошибки очистки также возвращаются в JSON; ошибки файлов и COM не классифицируются как бизнес-ошибки правил.
- Расширенный поиск не меняет рабочий исход даже при отличии диагностического результата из-за состояния JS. Это проверяется отдельным отрицательным сценарием.
- Учтены изменения упаковки из соседнего чата по запросу пользователя: перенос runtimes в DLL, перенос CSV_Converter.* и удаление лишних XML/PDB с исключениями для основных артефактов. Инструкции и локальные конфиги сохраняются.
- GUI после исправления служебных путей автоматически не запускался, как просил пользователь. Проверку выполняет пользователь по отдельному списку; успешная ручная приёмка не утверждается.
